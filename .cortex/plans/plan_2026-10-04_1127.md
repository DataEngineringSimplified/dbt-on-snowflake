## Context

- Files `02-put_full_load.sql` and `03-put_delta_load.sql` use Snowflake `PUT` commands (client-side file upload), which Flyway does **not** support.
- SnowSQL supports both standard SQL and `PUT`, so the GitHub Action will use **SnowSQL** instead of Flyway to run all four files in order.
- Connection credentials will come from GitHub repository secrets (configured in Settings > Secrets).

## Implementation Steps

1. **Create `.github/workflows/deploy-legacy-etl.yml`** — A manually triggered (`workflow_dispatch`) GitHub Action that:
   - Installs SnowSQL
   - Runs the 4 SQL files in order using GitHub secrets for connection (`SNOWFLAKE_ACCOUNT`, `SNOWFLAKE_USER`, `SNOWFLAKE_PASSWORD`, `SNOWFLAKE_ROLE`, `SNOWFLAKE_WAREHOUSE`)
   - Replaces `file://git-repo/` paths with the actual checkout path

2. **Update root `README.md`** — Add two new sections:
   - **GitHub Actions — Automated Deployment**: instructions on which secrets to configure and how to trigger the workflow
   - **Snowsight Workspace**: note that users can upload the `dbt-workspace/` folder to Snowsight and start running dbt directly
